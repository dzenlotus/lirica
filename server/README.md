# Генерация строк

Сервер запускается вместе с приложением через `npm run dev`; отдельно — `npm run dev:server`. Нужен Node.js 24. Слушает только `127.0.0.1:3001`.

По умолчанию используется локальный ChatMock: `http://127.0.0.1:8000/v1`, модель `gpt-6-luna`. Запустите и авторизуйте ChatMock заранее. Ключ для локального ChatMock не нужен. Пример настройки находится в `.env.example`; значения можно скопировать в `.env`. На 18 октября 2026 года проверен успешный запрос `/v1/responses` с `gpt-6-luna`, хотя `/v1/models` этого экземпляра ещё показывал старый каталог 5.6. Модель не заменяется автоматически.

Для другого совместимого сервера задайте `OPENAI_BASE_URL`, `OPENAI_MODEL` и при необходимости `OPENAI_API_KEY`. Внешний адрес должен использовать HTTPS. Ключ читается только сервером, не включается в клиентский код и не возвращается API. Внешний сервер без ключа переводит приложение в деморежим; ошибки настроенного провайдера показываются как ошибки и не маскируются демоподсказками.

`LIRICA_MODE=demo` включает конечный набор русских фраз без запросов к модели. Демоподсказки учитывают тему и несколько подготовленных семейств рифм; для незнакомого окончания используют рефрен. Они сохраняют введённое начало, но не гарантируют грамматику произвольного незавершённого слова, точную рифму или размер. В интерфейсе этот режим следует обозначать как демонстрационный.

`POST /api/suggestions` принимает строки, индекс активной строки, настройки и номер подборки. Возвращает ровно 10 уникальных полных строк, режим и индекс опорной строки. Опора — выбранная вручную строка либо предыдущая строка с той же буквой схемы в текущей строфе; пустая строка начинает новую строфу. Все начала строк сохраняются посимвольно. Неудачный, неполный, повторяющийся или меняющий начало ответ отклоняется. Сервер использует Responses API с `text.format`/JSON Schema и дополнительно проверяет ответ самостоятельно. Модель сначала выбирает `rhymeWord`, затем строит полную строку; совпадение этого слова с фактическим окончанием проверяется сервером. В строгом режиме для нескольких подготовленных семейств рифм выбор ограничен окончаниями из словаря; для остальных рифму подбирает модель. Близкая рифма и свободное созвучие не ограничиваются этим словарём: задача модели разрешает различия согласных и ассонанс соответственно. Это не является полноценной проверкой русской фонетики и ударений.

`POST /api/repairs` принимает `{ "lines": [...], "activeLine": 0, "settings": {...} }` и по явному запросу предлагает от одной до трёх полных замен активной строки. Начало разрешено переписать. Возвращает `{ "source": "исходная строка", "suggestions": [{ "id": "...", "text": "полная замена", "accentedText": "полная заме́на", "syllables": 5 }], "mode": "ai", "model": "gpt-6-luna" }`. `source` позволяет клиенту отклонить запоздалую подборку после изменения текста. `text` предназначен для применения по выбору автора; `accentedText` — отдельное отображение проверенного произношения, с автоматическими ударениями. Сам запрос ничего не меняет в стихотворении.

Модель получает исходный контекст и задачу сохранить смысл, образы и грамматику с минимальными изменениями. Последнее слово сохраняется с точностью до регистра и знака U+0301. Все исходные слова с ручными U+0301 сохраняются целиком, с тем же количеством повторений и в том же порядке; добавление новых ручных ударений запрещено. Эти ограничения проверяются сервером. Из максимум шести полученных вариантов отбрасываются повторы, исходная строка, переносы, строки длиннее 500 знаков и неподходящие окончания или авторские ударения. Затем длина и произношение проверяются независимо: словарь задаёт обычные ударения, контекстная модель разрешает только словарную неоднозначность. Неизвестное слово, неразрешённый омограф или любая ритмическая ошибка исключают вариант. Дополнительно последняя сильная позиция должна иметь реальное словесное или ручное ударение: нельзя создать новую стопу, просто добавив безударную частицу.

Однозначные кандидаты проверяются локально. Если проходит хотя бы один, возвращаются словарно проверенные варианты без дополнительного модельного запроса. Если не проходит ни один, но есть разрешимые словарные омографы, только такие кандидаты проверяются одним запросом ударений вместе с ближайшими исходными строками; этот контекст укладывается в ограничения разбора даже для предельного стихотворения. Нет повторных попыток генерации или обязательных трёх разборов полного текста. Если проходит только один или два варианта, возвращаются они. Если не проходит ни один, сервер отвечает `422 NO_VALID_REPAIRS` с понятным сообщением, без непроверенных замен. В деморежиме — `503 REPAIRS_UNAVAILABLE`. Пустая активная строка или свободный размер возвращают `400 INVALID_REQUEST`. Сохранённая рифменная опора не ограничивает выбор активной строки: окончание всё равно сохраняется. Смысловую и художественную пригодность варианта окончательно оценивает автор: проверка ритма не доказывает сохранение смысла.

`POST /api/prosody` принимает `{ "lines": ["Буря небо"] }` и определяет обычные словесные ударения. Однозначные словоформы проверяются локальным словарём RUAccent; модель выбирает только из словарных вариантов омографов по смыслу всего переданного текста. Размер и число стоп не отправляются модели. Ответ:

```json
{
  "lines": [{
    "text": "Буря небо",
    "words": [
      { "start": 0, "end": 4, "stress": 1, "status": "known" },
      { "start": 5, "end": 9, "stress": 6, "status": "known" }
    ]
  }],
  "mode": "ai",
  "model": "gpt-6-luna"
}
```

`start` включён, `end` исключён; все позиции — индексы UTF-16 в исходной строке, включая эмодзи и ручные знаки ударения. `stress` указывает непосредственно на ударную гласную. Каждое слово с русской гласной получает ровно одну запись. `known` означает однозначное словарное ударение либо допустимый словарный вариант, выбранный моделью по контексту; `weak` — безударное служебное слово или слово с определённым по контексту переносом ударения на предлог (например, историческое «и́з лесу»); `unknown` — неизвестная словарю многосложная форма или неразрешённый омограф. У двух последних `stress: null`. Одиночное «замок» без контекста остаётся `unknown` без запроса модели. Ручные ударения и ё имеют приоритет над автоматическим разбором. Сервер не вставляет знаки ударения и возвращает исходный текст посимвольно. Проверяются число записей, уникальность и диапазон индексов, неизменность слов и попадание ударения на гласную.

Однозначное словарное ударение имеет приоритет над модельным ответом: например, ошибочный модельный индекс для «голубыми» заменяется на словарное «голубы́ми». Для омографа модельный индекс принимается только из словарного списка; прочие варианты остаются `unknown`. Модельная догадка для отсутствующей многосложной формы не принимается. Перенос ударения с многосложного слова допускается только для подтверждённой словарём пары рядом с непосредственно предшествующим ударным предлогом; сейчас такая пара — историческое [«и́з лесу»](https://gramota.ru/poisk?mode=slovari&query=%D0%BB%D0%B5%D1%81%D0%B5). Модельный статус `weak` для произвольного «за молоко» не может отменить словарное «молоко́». Обычные односложные служебные слова и составные предлоги «из-за»/«из-под» по умолчанию безударны; автор может явно задать другое ударение.

Словарь не исчерпывает русскую лексику, а модель может ошибочно связать допустимый вариант омографа со смыслом контекста. Ручное задание ударения позволяет исправить такое чтение в конкретном тексте.

Если все словоформы однозначны, отмечены автором, содержат ё или имеют одну гласную, ответ рассчитывается без запроса модели. Неизвестные слова сохраняются как `unknown` и сами по себе не вызывают запрос. Полный контекст передаётся модели только при наличии словарной неоднозначности; при этом простые слова всё равно проходят словарную проверку. Поле `model` указывает настроенную модель контекстного выбора, в том числе в ответах, рассчитанных локально.

Словари лежат только в `server/data/ruaccent`, не импортируются клиентом и не включаются в браузерную сборку. Сжатые файлы читаются один раз через стандартные `fs`/`zlib`; их SHA-256 проверяются при загрузке. Используются 3 194 879 словоформ, 19 741 запись омографов и два словаря е/ё. Нейросетевой `accents_nn` и Python не используются. Точная ревизия, размеры, хеши и лицензия MIT приведены в [provenance словарей](./data/ruaccent/README.md). Ошибка загрузки или контрольной суммы возвращает `503 DICTIONARY_UNAVAILABLE`, без перехода на непроверенные модельные догадки.

В деморежиме `/api/prosody` возвращает `503 PROSODY_UNAVAILABLE`, а не вымышленные ударения. Неполный или некорректный ответ также возвращается как ошибка. Сервер хранит только 32 последних успешных разбора в ограниченном кеше памяти: ключ включает весь исходный текст, ревизию словаря и настройки провайдера. Изменение размера не вызывает новый разбор этого текста; изменение текста вызывает. Ошибки, отменённые запросы и запоздалые ответы после отмены в кеш не попадают.

Ограничения: 100 строк, 500 знаков в строке, 12 000 знаков в стихотворении, 32 КиБ в запросе; общие для всех методов 2 параллельных запроса и ожидание до 45 секунд. Для разбора ударений дополнительно разрешено до 600 слов с русскими гласными; больший текст возвращает `413 PROSODY_TOO_LARGE`. Бюджет ответа рассчитывается по числу слов, строк и знаков, до 28 тысяч токенов при предельном допустимом тексте. Локальный ChatMock удаляет `max_output_tokens` перед передачей дальше; независимо от этого Лирика ограничивает вход, размер принятого ответа (256 КиБ) и время ожидания. Закрытие клиентского запроса отменяет ожидание провайдера и освобождает место для следующего запроса. При необходимости контекстного выбора текст отправляется выбранному серверу генерации; Лирика его не журналирует и не сохраняет на диске. Словари локальны.

Подсчёт гласных показывает только примерное число слогов. Совпадение числа слогов не доказывает правильность ударений или стихотворного размера.

Проверки без платных запросов: `npm test`.

Явная проверка гибридного разбора с настоящей моделью: `node --expose-gc --env-file-if-exists=.env server/prosody.smoke.ts`. Два прохода через новые HTTP-серверы проверяют по 64 слова: известные строки Пушкина, контекстные «старинный за́мок» / «дверной замо́к», неопределённый одиночный омограф, ручное ударение, ё, историческое «Я и́з лесу вы́шел», 23 отдельных слова в новых примерах, в том числе «Звезды мерцают» / «далёкой звезды». Проверка требует `gpt-6-luna`, обращается к ней только для словарной неоднозначности и сообщает число обращений.

На локальной проверке 18 октября 2026 года оба прохода прошли полностью. Загрузка словарей заняла 2,05 с; после сборки мусора JavaScript-куча занимала 471 МиБ, RSS процесса — 1,28 ГиБ с учётом временных выделений при распаковке и разборе JSON. После загрузки словарные ответы занимали 1–4 мс, контекстные запросы — 2,53–7,91 с. Эти измерения получены на текущем компьютере с локальным ChatMock.

Формат API: [официальная документация OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses). Совместимость ChatMock проверена по локальному `chatmock/responses_api.py` и `chatmock/routes_openai.py`.
